# MCP-сервер для 1С-Битрикс (только чтение)

[![Тесты](https://github.com/shelezyaka/bitrix-mcp/actions/workflows/tests.yml/badge.svg)](https://github.com/shelezyaka/bitrix-mcp/actions/workflows/tests.yml)

Даёт языковой модели читать данные сайта по протоколу
[MCP](https://modelcontextprotocol.io) — каталог, разделы, свойства товаров,
цены и остатки, заказы. **Записи в модуле нет**: не отключена настройкой,
а отсутствует в коде.

Требования: 1С-Битрикс 22+, PHP 8.0+, модуль `iblock`.
Проверено в бою на Битрикс 26.650.0 / PHP 8.5 / Apache, каталог ~22 000 товаров.

Кроме данных модуль умеет показывать **устройство самого API** этой установки:
какие классы есть, какие у них методы и поля, как выглядит их исходник и что
лежит в файлах проекта. Это для тех, кто пишет код под конкретный сайт и не
хочет сверяться с документацией от чужой версии.

## Чем отличается от готовых решений

- **не выполняется на страницах сайта.** Запросы приходят на отдельную точку
  входа `/mcp/index.php`; обработчиков событий модуль не регистрирует вовсе.
  Решения, ловящие MCP-запросы в `OnProlog`, работают на каждом хите витрины;
- **белый список.** Инфоблоки и свойства выбираются в админке. Чего в списке
  нет — того для модуля не существует, произвольный фильтр не принимается;
- **токен показывается один раз** и хранится хешем;
- **журнал каждого обращения**, включая отвергнутые.

## Установка

1. Положить содержимое репозитория в `local/modules/itb.mcp/` — **имя папки
   важно**, по нему Битрикс находит модуль:

   ```
   git clone https://github.com/ВАШ_АККАУНТ/bitrix-mcp.git local/modules/itb.mcp
   ```

2. Проверить, что папка читается пользователем веб-сервера — клон, сделанный
   от `root`, Битрикс не увидит:

   ```
   chown -R www-data:www-data local/modules/itb.mcp   # или bitrix:bitrix
   ```

3. Админка → Marketplace → Установленные решения → «MCP-сервер (только чтение)»
   → Установить. Создаются три таблицы, точка входа `/mcp/index.php` и страница
   диагностики `/mcp/check.php`.
4. Настройки → Настройки продукта → Настройки модулей → **MCP-сервер**.

Обновление — `git pull` внутри папки модуля, затем открыть настройки: схема базы
подтягивается там, а не при обновлении файлов.

> ⚠️ **`local/modules/` доступна по HTTP**, в отличие от `bitrix/modules/`:
> запрет Битрикс кладёт только в свою папку. Модуль везёт свой `.htaccess`,
> но на чистом nginx он не читается — закройте папку правилом сервера:
> `location ^~ /local/modules/ { deny all; }`

Если установка отказала — откройте `/mcp/check.php` (только для администратора):
страница проходит путь до модуля по шагам и говорит, где именно теряет — нет
файлов, не видно папку `local`, не хватает прав. Она же показывает, доступен ли
на этом сайте путь через ORM (`?d7=1&ib=18,21`).

## Настройка

**Вкладка «Токены».** Кнопка «Выпустить» → значение показывается один раз, там же
готовая строка подключения. По умолчанию срок полгода; очистить поле — токен
станет бессрочным. Пока токенов нет, сервер не отвечает никому.

**Вкладка «Данные».** Галочка на инфоблок — его можно читать. Поле «свойства»
необязательное: пусто — отдаются все свойства, через запятую — только
перечисленные коды.

> Инфоблоки с персональными данными (заказы, обращения, подписки) открывать не
> стоит: читает их не человек, и ответы уходят за пределы сайта. То же касается
> свойств с себестоимостью и закупочными ценами.

**Вкладка «Настройки».** Разрешённые `Origin` (пусто — браузерам нельзя вовсе,
это верное значение по умолчанию), лимит запросов в минуту, срок хранения
журнала, движок чтения каталога и включение групп `orders`, `api` и `files` —
все три по умолчанию выключены.

## Подключение клиента

```
claude mcp add --transport http bitrix https://САЙТ/mcp/ \
  --header "Authorization: Bearer ВАШ_ТОКЕН"
```

Токен передаётся заголовком. В адресе он не принимается: адреса оседают в логах
веб-сервера, в истории и в реферере.

## Инструменты

Девятнадцать инструментов в пяти группах. Группа включается в настройках
модуля и отдельно выдаётся токену: одному можно дать только каталог, другому —
каталог и заказы, третьему — одну разведку API.

**Всегда доступен.** Не отключается: без него модель не знает, что ей открыто,
и начинает подставлять идентификаторы наугад.

| Инструмент | Что делает |
|---|---|
| `site_info` | версия Битрикса, подключённые модули, открытые инфоблоки и их свойства |

**Каталог** (`catalog`) — появляется, только когда открыт хотя бы один инфоблок.

| Инструмент | Что делает |
|---|---|
| `element_search` | поиск по названию, коду, разделу, активности, значениям свойств |
| `element_get` | один элемент со всеми заполненными свойствами |
| `section_list` | дерево разделов инфоблока |
| `product_get` | цены всех типов, остатки по складам, вес и габариты, торговые предложения |
| `store_list` | склады: название, адрес, телефон, режим работы |

Последние два появляются только при установленном модуле `catalog`: цены и
остатки лежат в его таблицах, а не в инфоблоке, и `element_get` их не видит.

> ⚠️ `product_get` отдаёт **закупочную цену**, если она заведена, — отдельным
> ключом `purchasing_price`.

**Заказы** (`orders`) — по умолчанию выключены. Появляются, только если на сайте
установлен модуль «Интернет-магазин» (`sale`): он есть не во всех редакциях.

| Инструмент | Что делает |
|---|---|
| `order_search` | отбор по номеру, статусу, датам, оплате, отмене |
| `order_get` | заказ целиком: корзина и свойства заказа |
| `order_statuses` | коды статусов этого магазина и их названия |
| `order_stats` | итоги за период: суммы, оплата, отмены, разбивка по статусам и покупателям |
| `user_get` | карточка покупателя по ID, логину или почте, с числом и суммой заказов |

`order_stats` считает `GROUP BY` в базе. Это дешевле и надёжнее, чем выбрать
сотню заказов и сложить их в диалоге.

> ⚠️ В свойствах заказа лежат имя, телефон и адрес покупателя. `order_get` и
> `user_get` отдают их наружу.

**Разведка API** (`api`) — по умолчанию выключена. Отвечает на вопрос «как
устроен код ЭТОЙ установки»; данных сайта не отдаёт.

| Инструмент | Что делает |
|---|---|
| `api_modules` | установленные модули с версиями |
| `api_class` | есть ли класс здесь, где лежит, публичные методы с сигнатурами |
| `api_entity` | таблица и поля ORM-сущности, с типами и ссылками |
| `api_source` | исходник класса или метода |
| `api_find_class` | файлы и классы в `lib` выбранного модуля |

> ⚠️ `api_source` показывает любой код сайта, включая ваш собственный. Читать
> произвольный файл нельзя — путь всегда даёт рефлексия по существующему
> классу, — но ключи, записанные прямо в коде, станут видны.

**Файлы** (`files`) — по умолчанию выключены. Дополняют разведку API там, где
она бессильна: компоненты, шаблоны, `php_interface` и обычные функции классами
не являются, и рефлексия их не видит.

| Инструмент | Что делает |
|---|---|
| `file_read` | файл по пути от корня сайта, целиком или куском строк |
| `file_list` | состав папки с размерами и признаком доступности |
| `file_grep` | поиск подстроки по коду в папке и вложенных |

### Границы чтения файлов

Читать разрешено из трёх мест:

| Разрешено | Запрещено |
|---|---|
| `/local/` — свой код, компоненты, шаблоны, `php_interface` | `/bitrix/php_interface/` — там `dbconn.php` |
| `/bitrix/templates/` | `/bitrix/modules/*/` вне `lib/` |
| `/bitrix/modules/*/lib/` | корень сайта, `/upload/`, `.git`, `node_modules` |

Поверх этого — два независимых слоя. По имени закрыты `dbconn.php`,
`.settings.php`, `.settings_extra.php`, `.env`, `.htpasswd`, `.my.cnf`, `.npmrc`
и приватные ключи. По расширению открыты только текст и код (`php`, `js`, `css`,
`html`, `tpl`, `json`, `xml`, `yml`, `md`, `txt` и подобные) — логи, дампы,
архивы, сертификаты и картинки отсекаются, не требуя перечисления.

Путь проверяется дважды: до разрешения симлинков и после, уже по настоящему
пути. `..` не схлопывается, а отвергает запрос целиком. Проверка не зависит от
Битрикса и прогоняется тестами (`tests/files.php`).

> ⚠️ Это ваш исходный код, и он уйдёт за пределы сайта. Ключи, записанные прямо
> в коде, станут видны: списком имён закрыты только обычные места их хранения.

`element_search` **не возвращает свойства**, пока их не назовут в `props`:
на живом каталоге карточка без свойств весит 398 байт, со всеми 138 — 17,6 КБ,
и выдача из двадцати строк доходила до 750 КБ.

### Два движка чтения

По умолчанию — ORM. Настройка «Читать через ORM (D7)» переключает способ
выборки; в каждом ответе есть поле `engine`, по которому видно, каким путём
получены данные.

| | `legacy` (`CIBlockElement`) | `orm` (`ElementXxxTable`) |
|---|---|---|
| свойства | запрос на каждый элемент | вместе с элементами |
| 50 элементов, 1 свойство | 0,41 с | 0,27 с |
| 50 элементов, 5 свойств | 0,38 с | 0,51 с |
| карточка со 138 свойствами | работает | работает |
| нужен `API_CODE` у инфоблока | нет | да |

ORM выигрывает, когда свойств просят мало, и проигрывает на нескольких: каждое
одиночное свойство — это JOIN. Свойства режутся на пачки по 30, иначе MySQL
отказывает («Too many tables», предел 61 таблица в соединении).

Инфоблок без `API_CODE` сущности не даёт — там модуль сам откатывается на
`legacy`, настройка при этом ни на что не влияет.

## Протокол

Streamable HTTP, версии `2025-06-18` и `2025-03-26`. Ответ — обычный
`application/json`, SSE не используется; `GET` и `DELETE` отвечают `405`;
сессий нет. Проверяется `Origin`, чужой `MCP-Protocol-Version` даёт `400`,
уведомление — `202` без тела.

## Разработка

```
php tests/protocol.php    # транспорт, рукопожатие, инструменты, JSON-RPC
php tests/tokens.php      # выпуск, срок, отзыв, права токена
php tests/expose.php      # разбор белого списка инфоблоков
php tests/api.php         # проверка имён классов и модулей
php tests/files.php       # граница чтения файлов
```

Тесты не требуют ни Битрикса, ни базы: `Protocol`, `Transport`, `Schema`,
`Token`, `Expose`, `Path` от них не зависят. Битрикс начинается в `Server` (сбор
запроса), `Data` и `Catalog` (каталог), `Orders`, `Users`, `Files` и `Orm/`.

## Что модуль не делает

Не пишет и не удаляет, не выполняет произвольные запросы, не меняет права и не
трогает настройки сайта. Заказы, покупатели и файлы читаются только тогда, когда
их группа включена в настройках и выдана токену; по умолчанию все три выключены.
